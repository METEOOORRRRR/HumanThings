# 검증 기록

검증일: 2026-09-13. Windows / Unity 6000.3.21f1.

## 2026-09-14 방 종료 오류 수정

- 사용자 Player.log에서 `WorldView.Update`의 `NullReferenceException` 확인.
- 원인: NGO의 비동기 Shutdown이 끝나기 전에 HostGame을 비웠지만 IsHost는 여전히 true로 노출됨.
- 수정: 종료 중 상태를 먼저 설정하고 Online/IsHost/CanConnect를 일관되게 판정. 종료 중 명령/음성/스냅샷 처리 중지, 화면·음성 상태 초기화, 종료 콜백 정리, 종료 완료 후에만 재접속 허용.
- PlayMode 6개 통과: 기존 물리 검사 3개 + 종료/재생성 3회 반복 + 네트워크 직접 종료 + 실제 호스트/클라이언트 종료 후 재접속.
- 결과: `QA/Lifecycle-results.xml`, `QA/Lifecycle.log`.
- 기존 실행 파일이 열려 있어 수정판은 `Builds/Windows-Fixed/EarthRecovery.exe`에 별도로 제공. 원본 Unity 프로젝트의 스크립트도 수정됨.

- 압축 전후 한국어 및 상태 보존.

## 자동 플레이 조건

6인 검증은 실제 NGO/Unity Transport 연결과 정상 이동·상호작용 명령을 사용했습니다. 호스트가 완료 상태를 강제로 지정하지 않았습니다. 세 현장 클라이언트가 각각 재료를 수집하고 설비를 복구했으며, 현장 정보를 별도 QA 통신으로 캠프 테스트 배우에게 전달했습니다. 이 통신은 사람이 음성으로 퍼즐을 설명하는 역할을 대신합니다.

게임의 기본 이동 속도 대신 8m/s를 사용하고 괴물을 제거해 제작·협동·회수 루프를 분리해서 검사했습니다. 따라서 이 실행의 약 76초 완료 시간은 실제 플레이타임 측정이 아닙니다. 별도의 PlayMode 검사로 물리와 안전지대를 확인했습니다.

QA 실행 인수가 없는 일반 실행에는 자동 플레이, 자동 퍼즐 해법, 괴물 제거, 속도 변경이 적용되지 않습니다. QA 코드 자체도 개발 빌드/에디터에만 포함됩니다.

| 4~6인 밸런스 | 실제 소통 시간, 괴물 밀도, 재료 배치, 운반 시간, 20분 목표 |

## 검증 중 수정한 항목

- 안전지대 볼륨이 NavMesh 수집 레이어에 포함되도록 수정.
- 한 번에 보내던 전체 상태를 UTF-8/Deflate로 압축해 6인 연결의 전송 큐 부담 감소.
- 완성품을 제작대와 겹치지 않는 로컬 좌표에 생성.
- 호스트의 게임 설정을 클라이언트에도 동기화.
- 기본 글자 재질이 벽 너머로 보이던 문제에 깊이 판정을 적용.
- 관전 카메라가 벽 뒤에 놓이지 않도록 장애물 검사를 추가.
