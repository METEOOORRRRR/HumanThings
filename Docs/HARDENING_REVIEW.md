# 예외 상황 방어 검토 · 2026-09-14

## 수정 범위

기존 기획과 정상 플레이 규칙을 유지하면서 세션 종료, 잘못된 입력, 반복 행동, 수명 관리 경계를 보강했다. 모든 장애가 없어졌다는 의미는 아니다.

## 자동 검증

- EditMode 40개 통과: 기존 임무 완료 시나리오 포함. 새 방어 테스트 16개 추가.
- PlayMode 8개 통과: 실제 NGO 연결, 호스트 종료와 재접속, 반복 방 생성/종료, 잘못된 주소, 손상 패킷 연결 종료, 물리 벽과 안전지대 검사.
- 수거·폐기 2,000회 후 재료 슬롯 120개 유지 및 수량 보존 확인.
- 결과 파일: `QA/Hardening-EditMode.xml`, `QA/Hardening-PlayMode.xml`.
- 최종 Windows 빌드 성공, 빌드 오류 0개. 전달 DLL과 검증 빌드 DLL의 해시 일치 확인.
- 최종 실행 파일 6개를 실제 연결해 3종 제작·퍼즐·회수 완료. 6개 모두 PASS 및 정상 종료 코드 0.
- 살아 있는 요원 음성 중계, 사망 요원의 생존자 대상 음성 차단과 조작 차단 통과.
- 다중 프로세스 결과: `QA/Hardening-final-six/*-result.txt`, 로그 및 화면 PNG도 같은 폴더에 보관.
- 전체 임무 자동 검증은 QA 전용 속도 8, 괴물 비활성화로 수행했다. 일반 플레이 난이도·장시간 생존 검증과는 구별한다. 안전지대·추적 목적지·충돌은 별도 테스트로 검증했다.
- 최신 실행 파일: `Builds/Windows-Hardened/EarthRecovery.exe`. 임시 검증 프로젝트는 결과 보존 후 정리했다.

## 남은 검증과 의도된 제한

- 실제 마이크 권한 거절, 장치 분리/재연결, 여러 사람의 음성 품질은 하드웨어 수동 검증 필요.
- 외부 인터넷·NAT·방화벽·장시간 패킷 손실·기기 절전 복귀는 별도 환경에서 검증 필요.
- 호스트 이전·인터넷 매치메이킹은 현재 범위 밖. 호스트가 나가면 방이 종료된다.
- 클라이언트 명령을 검증하지만, 신뢰할 수 없는 호스트에 대한 경쟁 게임 수준의 부정행위 방지 시스템은 아니다.
- 신규 에셋·씬·규칙 추가 시 해당 경계에 맞춰 검증 조건과 테스트도 함께 갱신해야 한다.
- 프로토타입의 메모리 부족, 드라이버 오류, Unity 엔진 자체 오류까지 복구한다고 보장하지 않는다.

사용 중인 원본 에디터를 강제로 닫지 않고 `EarthRecovery-HardeningValidation` 복사본에서 테스트·빌드했다. 기존 PDF와 기존 Windows 실행 파일은 보존한다.
