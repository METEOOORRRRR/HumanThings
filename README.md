# Human Things v0.3

A co-op horror game about exploring a ruined Earth, recovering relics of human culture, and surviving the infected.

## 저장소에서 시작

Unity 6000.3.21f1로 저장소 루트 폴더를 열고 `Assets/Scenes/Expedition.unity`를 실행한다. 필요한 패키지는 `Packages/manifest.json`과 `packages-lock.json`에 고정되어 있다. 기본 에셋, 테스트 코드 및 `.meta` 파일을 포함한다.

실행 파일, Unity 캐시, 로컬 QA 로그/스크린샷은 Git에 포함하지 않는다. 아래 빌드 폴더와 QA 경로는 기존 개발 환경의 산출물 경로이며, 새로 복제한 환경에서는 직접 빌드/테스트해야 한다. Windows 실행 파일은 Unity 메뉴 `Earth Recovery > Build Windows Prototype`으로 `Builds/Windows`에 생성한다.

Unity 6000.3.21f1 / URP / Netcode for GameObjects. 기존 `EarthRecovery` 프로젝트를 유지한 기능 검증 버전이다. 시각 자산은 교체 가능한 기본 도형이다.

## 실행

1. Unity Hub에서 기존 EarthRecovery 프로젝트를 열고 `Assets/Scenes/Expedition.unity`를 실행한다.
2. 또는 `Builds/Windows-HumanThings-v03-ThirdPerson/EarthRecovery.exe`를 실행한다. 사용자 기존 실행 경로를 Revision2로 직접 갱신한다. 상위 폴더의 `HumanThings-Latest.cmd`도 같은 경로를 연다.
3. 한 명이 방을 만들고 나머지가 호스트의 IPv4 주소와 포트로 접속한다. 같은 PC에서는 `127.0.0.1`을 사용한다.
4. 기본 4명 이상 준비 완료 후 호스트가 시작한다. 최대 6명. 2인 디버그는 GameRules의 minPlayers를 명시적으로 변경해야 한다.

프로토콜 5를 사용하므로 모든 참가자는 로비 제목이 Revision2인 실행 파일을 사용해야 한다. 이전 파일은 `Builds/Archive`에 백업하며, 이전의 다른 빌드 폴더와 혼용하지 않는다. 호스트 이전이나 인터넷 Relay/매치메이킹은 제공하지 않는다.

Revision2는 호출벨 제거와 앞선 수정 전체를 포함한다. 참가 요청 중에는 준비/시작 버튼 대신 접속 상태와 취소 버튼만 표시하고, 서버 연결 및 플레이어 정보 수신 후에 대기실을 연다. 실패하면 접속 화면으로 복귀한다.

## 새 플레이 흐름

미확인 표본 3개 배정 → 고철 수집 → 필드 복원기 3개 중 하나에서 장소별 모듈 제작 → 해당 장소에서 모듈 설치 → 스킬체크 → 캠프와 최종 협동 퍼즐 → 운반 → 캠프 회수 및 이름 공개.

- 5개 구역에 각 3개 장소, 총 15개 장소가 매판 존재한다.
- 45개 물건 중 서로 다른 장소·가능하면 서로 다른 구역의 3개를 선정한다.
- 고철은 한 종류다. 모듈은 기본 고철 3개와 3초가 필요하다.
- 모듈 제작을 절반 이전에 취소하면 전액 반환하고, 절반 이후에는 반환하지 않는다.
- 올바른 장소에서 설치 버튼을 2초 유지한다. 시설 복원 후 추가 파밍 재료는 필요 없다.
- 물건 이름은 회수 전 `???`다. 캠프는 상세 정보, 외부 요원은 요약을 받는다. 장소 진입과 조립 33/66%에서 단서가 공개된다.
- 회수 시 도감에 실제 이름·설명·화성 코멘트를 등록한다. 도감은 로비/종료 화면에서 연다.
- 이전 도감 등록 여부와 관계없이 현재 임무의 물건 이름은 회수 후 공개한다. 기존 도감 기록은 보존한다.
- 복원 제작기는 주황색이며, 5개 구역의 전체 15종 시설 모듈을 한 화면에 표시한다. 임무 대상 자동 선별이나 강조는 하지 않는다.
- 시설 내부 청록색 단말기 근처에서 E로 상태창을 연다. 모듈이 없거나 임무 대상이 아니어도 상태 확인이 가능하다.
- 캠프 단말기는 표본 3개의 단서와 진행 상태, 협동 연결을 표시하며 시설 정답을 적지 않는다.
- 캠프 지도는 5개 구역을 색상으로 구분하고 15개 시설 위치를 항상 표시한다. 미발견 이름은 ??, 발견 후 실제 이름을 표시한다.
- 산소 고갈·전원 사망 시 실패. 혼자 남으면 캠프에서 동면하여 종료할 수 있다.

## 조작

플레이어 시점은 3인칭이다. 자기 캐릭터 뒤 3.6m에서 마우스로 시점을 회전하며, 벽이나 바닥에 가려지면 카메라 거리를 자동으로 줄인다. 사망 후 생존자 관전에도 같은 충돌 처리를 사용한다.

| 입력 | 동작 |
|---|---|
| WASD / 마우스 | 이동 / 시점 |
| Shift | 달리기, 외부 소음 발생 |
| E | 시설 단말기 근접 상호작용, 고철·모듈·완성품 수거, 복원기·캠프 단말기 |
| F | 손전등 |
| G | 완성품 내려놓기 |
| R | 운반 중 물건 활성화/비활성화. 라디오, 카메라, 우산 등의 반응에 사용 |
| Tab | 고철·모듈 가방 |
| Space | 현장 제작 시작/타이밍 판정 |
| 설치 버튼 유지 | 올바른 모듈 설치 |
| V 유지 | 마이크를 켠 뒤 무전 송신 |
| Esc | 메뉴/마우스 잠금 전환 |
| 오른쪽 방향키 | 사망 후 다음 생존자 관전 |

## 콘텐츠와 설정

`Assets/Resources/HumanContent.asset`이 콘텐츠 진입점이다. `HumanThings` 폴더에 구역·장소·물건·괴물·레시피·퍼즐 자산과 프리팹이 있다. 기존 `GameRules.asset`에서 산소, 기본 인원, 복원기 거리, 환불 기준, 우천 여부 등을 조절한다.

괴물은 M01 소음, M02 빛 누적, M03 경로 배회, M04 통신 모방, M05 오염 공급원, M06 정지 감지를 사용한다. 라디오·카메라·우산·가족사진 반응과 행동 앵커는 데이터로 연결된다.

괴물은 분산된 출발점에서 기본 순찰하며, 일반 개체는 랜덤 목적지, 통근자는 지정 경로를 사용한다. 경로 실패나 이동 정체 시 재탐색하고, 기억 행동 중의 의도된 일시 정지는 유지한다.

**미정/통합 주의:** 현재 필터 소모가 없으므로 M05의 기본 오염 공급원은 0이다. 공급 인터페이스는 구현되어 있다. 주파수·압력밸브는 이전 프로젝트에 상세 규칙이나 구현이 없어 임의로 추가하지 않았다. 현재 임무는 회전·인형뽑기·미로 프로필을 사용한다.

## 음성과 저장

기존 8 kHz 무전과 `IVoiceMimicSource`를 사용한다. 에코는 최대 1초의 최근 송신 음성을 RAM에서 모방하거나 미리 생성한 한국어 생활 문장을 재생한다. 플레이어 녹음을 파일로 보관하지 않는다. 외부 AI 음성 서비스는 연결하지 않았다.

Archive는 호스트 로컬 공유 저장이며 `Application.persistentDataPath/human-things-archive-v1.json`과 백업 `.bak`을 사용한다. 클라이언트에는 호스트 도감을 동기화한다. QA 실행은 실제 도감에 쓰지 않는다.
